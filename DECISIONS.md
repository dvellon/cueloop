# Engineering decisions

| ID | Date | Decision | Rationale | Revisit trigger |
|---|---|---|---|---|
| D-001 | 2026-09-01 | Name V1 **CueLoop** and Autodesk V2 **CueLoop Bridge**. | “Bridge” communicates detachable multi-space utility beyond studios while preserving the technical lineage. | Trademark/confusion check or application feedback. |
| D-002 | 2026-09-01 | Target Best Social Impact for V1; treat Best in Show as upside. | The private, accessible awareness use case maps directly to the official category while the uncertainty pipeline supports broad usefulness. | Official category/rules change. |
| D-003 | 2026-09-01 | Start with 16 kHz, mono, signed 16-bit PCM over UDP on a trusted local network. | It is simple, inspectable, about 256 kbit/s before overhead, and sufficient for the target demonstration. | Measured loss, latency, runtime, or network contention is unacceptable. |
| D-004 | 2026-09-01 | Version packets, include pod/sequence/sample-clock metadata and CRC32, and keep payload at 20 ms (320 samples/640 bytes). | Packets fit comfortably below common MTUs, make loss visible, and align with streaming audio cadence. | Hardware profiling shows a different frame size is materially better. |
| D-005 | 2026-09-01 | Keep raw audio memory-only and bounded; persist only event metadata and explicit user feedback. | This makes the privacy promise technically enforceable and limits impact of device compromise. | A user explicitly enables a documented diagnostic capture session. |
| D-006 | 2026-09-01 | Use a model adapter: deterministic simulation classifier for tests and optional TFLite/YAMNet-compatible inference for real evaluation. | The event engine remains fully testable before weights/hardware while simulated outputs cannot be confused with measured model quality. | A better-supported official App Lab audio model is benchmarked. |
| D-007 | 2026-09-01 | UNO Q Linux owns networking, inference, policy, API, and event history; STM32 owns button handling and physical cue timing. | It makes meaningful use of both processors and keeps timing/recovery deterministic. | Official APIs or target profiling contradict the split. |
| D-008 | 2026-09-01 | V1 supports a focused initial vocabulary: door knock, alarm/beep, dog bark, and attention call, plus unknown/background. | Four interpretable classes permit honest per-class testing and a clear demo. | Evaluation shows a class is unreliable or another is substantially stronger. |
| D-009 | 2026-09-01 | Treat CueLoop as an awareness aid, never a certified alarm, security, or medical device. | Avoids unsafe substitution and unsupported regulatory claims. | Never relax without formal certification work. |
| D-010 | 2026-09-01 | Use official App Lab folder structure and Bridge APIs; keep the core Python package runnable outside App Lab. | This supports official integration and fast desktop simulation with one code path. | App Lab packaging constraints require a thin adapter change. |
